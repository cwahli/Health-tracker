## 6. Learnings — the traps, so nobody re-pays them

1. **Run gates on a clean checkout of `main`, never on the deploy clone.** The
   auto-deploy rewrites `src/git-version.generated.ts` locally, which turned
   `card-19`'s *own* gate red. Closing on the deploy clone's answer would have
   been closing on a host artifact.
2. **A green gate is necessary, not sufficient.** `assert-spec-diff.mjs` compares
   the *working tree* against `allowed_files`, so on a clean tree it passes
   vacuously. For thin-gate packets, verify the **substance** (the code path, the
   test that would fail without the change) before closing.
3. **`specs/done/` is the signal, not `status:`.** 37 of the 40 packets already
   in `done/` still said `status: locked`. The process doc
   (`docs/agent/LOCKED_SPEC_PROCESS.md`) requires `status: done`; the nine closed
   this session set it.
4. **Squash merges make every worktree look unlanded.** At the time of writing
   **86 of 89** worktrees returned a non-zero `git rev-list --count
   origin/main..HEAD` while their work *is* on `main`, because the squash mints a
   new sha. Treat branch counts and "HEAD subject not in main" as **noise**; use
   `WORK_QUEUE.md`.
5. **`git log -S<packet-id>` only finds mentions in file *content*.** A packet
   that was implemented but never named in a handover line shows zero hits — that
   is not evidence it is unstarted. Cross-check `AI_HANDOVER.md` and commit
   subjects.
6. **A sensor that crashes instead of reporting red hides the red.** It happened
   in the Doctor's readiness check; guard with optional chaining so a gate always
   prints its verdict.
7. **Three self-referential sensor bugs were found and fixed this engagement** —
   a caller regex matching 1 of 3 invocations; a file-scoped `inHelper` exempting
   every call site; the identity gate flagging *enforcers* that merely name a
   banned method. When a gate fails, first ask whether the gate is wrong.
8. **Telegram `setMyName` is rate-limited to the point of uselessness** under
   backoff (429 for ~40 min). Bot identity is now protected by a CI gate that
   bans `setMyName`/`setMyUsername`/`setMyDescription` anywhere in `scripts/`,
   so **names are set once, by hand, and never in code**.
9. **The registry `name` is a human label, not the Telegram name.** Telegram only
   stores a custom title on an admin, which is why seat identity needs promotion.
   No bot is to be renamed for a seat — the tag identifies them (operator ruling,
   2026-10-02).
